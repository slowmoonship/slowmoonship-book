# 前言｜从一个按钮走到一份可分析的记录

你在钱包里点击“发送”，或者把一种代币换成另一种。几秒之后，界面出现成功提示。背后发生的过程却比一条提示复杂：请求经过授权，网络组织历史，执行客户端运行代码，合约读取并修改状态，索引服务再把结果变成可以查询的表。

《慢月船：链上数据之路》的 Ethereum 篇，沿这条路径展开。我们从一笔真实的一 ETH 转账开始，再去理解账户、程序、内部调用与事件。最后进入 Dune，用 SQL 对照同一类记录，尝试还原一笔真实兑换。读者不需要先学会部署合约，也不需要背下全部指令。

这本书主要写给三类人：想读懂钱包与浏览器的普通读者，懂一点 SQL 的分析师，以及希望把链上记录写成可靠结论的研究者。三类人的起点不同，共同的问题却相似：一个地址究竟代表谁，一条事件能证明什么，为什么同一笔操作会出现在很多张表里？

我们会把专业词放回具体场景。账户不是一张实名用户卡，交易不是所有业务动作的通用总数，事件也不是自动覆盖所有资产变化的凭证。类比帮助入门，随后会明确真正的结构与适用条件。你可以按顺序阅读，也可以通过目录回到某个问题。

全篇以 Ethereum Mainnet 为范围。执行层与共识层都需要理解，但重点是它们留下的数据。L2 只在数据发布与结算关系上出现，不混入其他网络的账户与交易教程。历史机制与当前主网规则分别说明，避免把多年前的经验当成今天的永久结论。

图和 SQL 是正文的一部分。图展示实体与关系，源文件可以继续编辑；SQL 保留固定时间与真实交易身份，让读者知道查询要找什么。复杂字节不被刻意隐藏，也不会要求读者先成为 Solidity 开发者。我们只拆开支撑当前问题所需的部分。

读数据时，最值得培养的是分层判断。请求告诉我们提交了什么，轨迹帮助展开执行过程，日志保存程序显式声明，状态描述保存的内容。平台进一步解码与加工这些记录。层次之间相互关联，却没有一个名称能够代替全部证据。

本书也把“看到了什么”和“还缺什么”写清楚。新 SQL 的运行状态、真实案例的材料范围与来源日期都能够追溯。一个明确边界的结论，比一句缺少材料的保证更有价值。学习的目标是独立分析，而不是对某个网站的标签产生新的依赖。

如果你能在读完以后打开一笔陌生交易，区分顶层操作与内部调用，逐资产解释金额与费用，选择正确的数据粒度，并说明结论的限制，这一篇便完成了它最重要的任务。现在，让我们从发送一 ETH 开始。
