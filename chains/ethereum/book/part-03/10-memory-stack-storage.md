# 10｜Stack、Memory 和 Storage 为什么不能混着看？

执行合约时，程序会暂存中间值，也会保存交易结束后仍然需要的数据。好比计算时用草稿纸，账目要另行记入账簿。类比到这里就够了：EVM 的临时空间与账户持久状态有具体规则，不能用“都是存储”一笔带过。

栈（Stack）暂存指令操作的值。EVM 是基于栈的机器，算术、条件判断和许多其他操作从栈中取得参数，再把结果放回去。分析交易通常不需要逐条阅读 Opcode，但要知道低级执行日志中的栈快照是某一步的中间状态，不是一个账户当前全部资产。

调用帧（Call Frame）可以理解为一次调用正在执行的工作现场，带有自己的输入、资源和上下文。内存（Memory）是这个调用帧执行期间使用的临时字节空间。程序可以把参数、返回内容或待发日志的数据放在这里。调用新的合约，会进入另一个调用帧，它的 Memory 不是直接继承上一帧的同一张可写表。父子调用通过明确的输入和返回数据交换内容。

持久存储（Storage）属于账户执行状态。它用槽位组织内容，存取按协议收取 Gas。普通合约调用在被调用账户的上下文修改存储；Delegatecall 则可以使用别处的代码修改调用方上下文的存储。数据位置必须由调用语义判断，不能只看字节码属于哪个地址。

瞬时存储（Transient Storage）又是一种不同的机制。它可以在同一交易内跨相关调用使用，但不会像持久 Storage 那样留到后续交易。它也不是 Memory 的另一个名字。分析师遇到临时锁或同交易协调变量时，不应该把它们解释为永久账户账簿。

Calldata 是提供给当前调用的输入字节，通常不能由被调用程序直接改写；Return Data 是调用返回的字节。它们可能承载金额，却不因此成为余额。一个函数返回了数字 100，只能说明本次调用返回这段内容；是否对应真实资产，要看函数定义与当时状态。

Case 04 中，Router 的输入参数指定最小单位数量，Pool 返回两个带符号数量，WETH `balanceOf` 返回池余额。三个位置都有“金额”，语义却不同：请求数量、执行结算差额、特定读取时刻的余额。把它们全当作 Transfer 相加，会混合意图、结果和存量。

如果只需要研究一笔兑换的主要路径，调用级 Trace 通常比完整指令级 Trace 更易读。要证明某个槽位怎样写入，才进一步查看合约布局和状态差异工具。工具返回的细节越多，不代表研究结论越完整；选对数据层级才是关键。

本章的验证练习是给这三个数字各写一个单位和时间位置：它是 Wei、代币最小单位还是无单位参数？它来自执行前、执行中还是执行后？能回答这两问，便已经避开很多基础错误。

把一次余额读取返回的数值保存下来，可以与稍后的再次读取比较。若两次读取位于同一交易内不同位置，它们观察的可能是同一账户的不同中间状态。这正是案例中支付前后余额核对的意义。

不过，调用轨迹只显示读取返回值，不自动告诉我们合约为什么采用这个值。要解释最低输出、支付验证或缓存规则，仍需合约语义。数据详细到字节层，并不会让业务含义自行浮现；研究者必须把位置、类型与代码规则连接起来。
