# 前言｜先找账本，再解释数据

你在 Avalanche 钱包里看到 AVAX，准备拿一部分去质押，却被要求从 C-Chain 移到 P-Chain。这个小问题足以打开整篇书稿：同一个网络，为什么有多个资金位置、不同交易类型和不同数据模型？

《慢月船：链上数据之路》（slowmoonship: Gateway to Onchain Data）的 Avalanche 篇，沿一条由浅入深的路线回答它。先辨认 Primary Network 的 C/P/X 三条独立链，再理解共识与虚拟机的职责；随后进入平台对象、UTXO 和原子转移，最后讨论独立 Avalanche L1、验证者管理和跨链消息。

运行地图（Runtime Map）解释谁做什么：节点维护哪条链，虚拟机怎样改变状态，平台怎样记录注册，消息怎样得到认证。数据地图（Data Map）解释留下什么：EVM 交易和收据、平台交易、资金输出、注册状态与消息事件。把两张图连起来（Connect the Two Maps），才可能回答一项操作究竟走到了哪一步。

普通读者可以按目录顺序阅读，每章只集中解决一个问题。会 SQL 的读者可以进一步打开表卡和示例；专业研究者可以由案例索引追到实际请求、原始响应与计算结果。正文不要求先读 Ethereum 篇；共同的 EVM 概念在此作必要解释，需要更多执行细节时，可参阅 [Ethereum 篇](../../ethereum/README.md)。

本篇采用少量真实案例反复连接不同知识点。C→P 的主网原子转移可以追到后续委托；X-Chain 的多输入交易让输出模型具体可见；Beam 的创建、转换、注册和独立链执行展示 L1 的多个观察面。跨链消息样本只有源侧证据，这个缺口也明确保留，不用一张流程图替它补齐目标成功。

研究基准日为 2026 年 10 月 12 日。Mainnet、Fuji 与 Local 不混用。历史案例按自己的发生日期解释：Helicon 前的 C-Chain 执行与今天的 Continuous Execution 有时序和计费差异，Etna 前的 Subnet 与转换后的 L1 有成员管理差异。更新不是把旧术语全部替换，而是为每份记录找到正确版本。

一份完整书稿不应承诺完整观察了整个网络。Dune 的 C-Chain 表不代表全部 Avalanche；官方索引服务也有覆盖、限流与加工语义。这里分开真实直接数据、计算推导、官方协议说明和教学模型。未执行的 SQL 不附虚构结果，未取得的目标消息与合约状态不宣称成功。

当你读完后再次遇到“创建自己的区块链”，希望你能够问得更具体：创建了哪个对象，谁在验证，哪里能找到真实区块，什么资产支付执行费，哪项管理记录仍未对齐，跨链业务的目标证据在哪里。由这些可检查的问题组成的网络认知，才是本篇想交给你的工具。
