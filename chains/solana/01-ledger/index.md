# 01.00 把一笔行为放回账本

查询某个钱包过去一天的行为，看起来只需要过滤时间。但“一天”属于哪个时区？数据只包含成功交易吗？投票交易是否算在内？在解释金额和程序之前，先要给所有行为一个共同坐标，并固定分析总体。

账本（Ledger）保留网络接受的历史。区块（Block）把一组交易组织在一起；交易是提交执行要求的单位。Slot 可以译为时隙：网络为出块安排的编号机会。编号不断推进，但不是每个机会都在最终链上留下区块。因此，当你看到 Slot 的数字跳跃时，不能把它理解为数据库自动递增主键丢了一行。

Block Height 是区块高度，沿链统计已形成区块的数量。Slot 与 Height 都能表示账本位置，但测量对象不同。分析师通常用 Slot 连接区块和交易，用区块时间（Block Time）划定日期范围，用交易在块内的索引区分位置。它们各有用途：Slot 不是秒数，时间戳也不能唯一识别交易。

账本还有确认程度。刚被某个节点处理的交易，与已获得更强网络确认的交易，风险边界不同。RPC 的 commitment 参数让读者明确所需的确认程度。历史仓库统计与低延迟监控也有不同诉求：前者重视稳定的样本，后者接受更早但尚可能变化的观察。没有声明确认与覆盖的时间序列，容易把暂时延迟误读成业务下降。

进入 Dune 后，我们先观察体量较小的 `solana.blocks`。它的一行代表一个被索引到的区块，提供 `slot`、`height`、`time`、`date` 及交易计数。区块表中的统计可以帮助我们研究网络活动，而无需先展开全部交易。需要看谁付费和哪些账户变化时，再进入交易层。

这里必须先固定“交易”的总体。Dune 的 `solana.transactions` 排除投票交易，投票记录在 `solana.vote_transactions`。投票是验证者参与网络共识的行为，不应直接与普通应用行为合并成用户活跃度。即使非投票交易更接近应用活动，它也可能来自机器人，不能自动等同于真人操作。

现有看板的区块查询 8435308 正好体现这条路线：先按日期聚合区块，再分别保留成功、失败和投票计数。交易图 8435334 复用这些区块统计。复用查询定义方便维护，但不意味着再次运行派生 SQL 必然免费；本篇只读取定义，不据此重新触发历史扫描。

本模块依次解决三个问题：Slot 为什么不等于 Block；时间和最终确认怎样影响观察；区块表怎样回答网络活动问题。到模块末尾，你应能解释统计窗口和分母，再把下一模块的交易放回这个总体里。这个准备会使后面的每个 JOIN 更容易核查。
