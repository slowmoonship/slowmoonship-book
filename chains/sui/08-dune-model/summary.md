# SUI 08 小结｜先定粒度，再写关联

六表围绕事务主干组织历史、对象关系、状态、调用和事件。当前 API 已确认表名与字段，其中调用表为单数 sui.move_call；额外的 Package 和包装表按问题扩展。

每张表都有自己的记录单位。事务行不是调用行，对象关系不是资产转移，对象历史不是当前快照。连接图给出分析路径，但没有替数据库声明外键，也不能证明候选键唯一。

可靠查询先固定主干集合，再验证分支键与覆盖。仅用于筛选时可用 EXISTS；需要多个指标时先在目标粒度聚合再连接。DISTINCT 不能补救没有定义的口径，也不能自动消除金额复制。

字段类型、日期范围和 JSON 结构同样需要核对。接口与平台可以提供不同展开方式，最新协议累加器变化也不能默认全部出现在对象表。API Schema、静态 SQL 和成功执行结果分别记录验证状态。

下一模块将模型落实到单笔事务、Swap 与对象历史。真实案例保留完整标识和官方接口快照；Dune SQL 的运行缺口单独披露，让读者可以在条件具备后复现验证。
