# SUI 10 小结｜让结论与证据范围一致

从单笔事务扩展到钱包或协议，首先变化的是边界。Sender、费用承担者、Owner 和接收者代表不同角色；地址也不能自动等于一个现实用户。统计活动时，先定义行为与主体，再计数。

资金状态、事务净变化和池步骤流量是不同观察。Coin、Address Balance、业务对象与存储返还都可能影响结果。多主体正负变化不一定能唯一配对成资金路径，内部路由也不能重复当作用户最终成交量。

协议分析需要 Package 谱系与业务类型。一个最新 ID 无法天然覆盖全部历史和路由。调用、事务、事件、对象与用户指标，应分别保留粒度和成功条件。流动性估值还需要协议规则、状态位置与价格证据。

审计报告最终应让另一位分析师知道：结果代表什么范围，来源位于哪笔事务和哪个版本，SQL 是否执行，缺口在哪里。遇到不完整覆盖，保留较窄结论；遇到未知，保留未知，而不是静默填零。

全篇总结将回到一个最具体的问题：现在给你一笔陌生的 Sui Transaction，怎样完成一份有证据、有边界、可以复核的解释？
