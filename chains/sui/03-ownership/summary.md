# SUI 03 小结｜归属、访问和版本分开判断

对象的归属、事务的访问方式和执行使用的版本，是三个相关但不同的问题。Address-Owned、Shared、Immutable、Party、Object-Owned 与包装形式，提供不同的访问条件，不能只保留一个 Owned/Shared 标签。

Shared 允许引用，不等于允许任何业务修改。Immutable 是对象不可变状态，不等于本次只读借用。Party 保留单地址拥有，并采用相应共识版本机制。父子拥有与包装又有不同的存储和查询可见性。

当前网络对所有事务进行共识排序；对象文档中的 Fastpath 版本术语不应被直接解释为绕过这条共同生命周期。排序确定以后，执行引擎仍可以并行推进互不冲突的事务。并行能力取决于实际输入、访问方式和依赖。

混合访问的 PTB 是理解这些关系的最好例子。同一 Swap 同时需要 Coin 授权和 Pool 状态，两个输入共同进入事务执行，业务原子边界不会因 Ownership 不同而被拆开。

数据分析时保存原始 Owner、访问角色、版本和执行结果，再构造分类。对象被引用、读取、修改和拥有分别代表不同事实；将它们分开，后面的 SQL 才能给出清楚的活动指标。
