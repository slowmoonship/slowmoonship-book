# 01.2 | 创建、修改、转移、包装与删除

对象历史不只是“余额发生变化”。创建产生新身份；修改改变内容或元数据；转移改变访问主体；删除使对象退出可用状态；包装则把对象放入另一对象的内部结构。观察这些动作时，必须分清身份是否继续存在，以及是否仍可通过独立 ID 直接访问。

创建一个新的 Coin，与给既有 Coin 增加余额，是不同对象事件。前者可能增加一个 Object ID，后者保留身份。将一个 Coin 合并进另一个 Coin，来源对象可能被消费而删除，价值却继续存在于目标对象里。对象数减少不等于资产消失。

转移同样需要看对象语义。把一张 NFT 从 Alice 交给 Bob，通常涉及同一 ID 的 Owner 变化。把资金交给 Bob，则可能转移整个 Coin，也可能 Split 出新 Coin 再转移，甚至进入 Address Balance。业务上都能叫“转账”，对象历史却不同。

包装意味着对象作为值进入另一对象的字段。它不再作为普通独立输入被直接使用，但身份可以在解包后继续沿用。Wrapped Object 与 Object-Owned Object 不是同一种可见性：后者仍可能独立存储，通过父对象控制访问；包装则需要读取承载它的外层结构。[Wrapped Objects](https://docs.sui.io/develop/objects/object-ownership/wrapped)

删除也不能只凭查询返回空值来判断。历史服务可能保留删除标记，当前接口可能返回不存在，归档仍可能提供旧版本内容。索引延迟、历史修剪和错误版本参数都会影响查询。可靠的删除结论需要把对象状态标记与对应事务 Effects 连接起来。

追踪生命周期时，可以把记录按对象版本组织，再用 Transaction Digest 或 `previous_transaction` 寻找引发变化的事务。不过“previous”在这里指产生该输出状态的上一相关事务，不是时间上紧邻的全网事务。版本链与 Checkpoint 序列描述不同层次。

当一个对象暂时被包装，历史里可能出现不可独立访问的间隔。把这个间隔误作永久删除，后面的解包会看起来像身份复活。正确解释应保留包装与解包的状态含义，不能只把所有无法匹配对象内容的关系行归为脏数据。
