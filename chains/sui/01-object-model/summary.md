# SUI 01 小结｜先确定身份，再理解状态

Object 提供状态身份，Version 把身份放进历史，Digest 承诺一个特定状态的内容与元数据。Type 和 Owner 分别说明对象是什么、如何被访问。它们一起帮助我们认识对象，但承担不同问题。

分析对象数据时，先明确结果要代表当前存活对象、历史版本，还是事务与对象的关系。三个集合都可能围绕同一 ID 展开，数量却不同。特别是 Coin，Split、Merge、转移和余额累加器会让对象数量与资金数量明显分离。

不要把版本间隔当作修改次数。版本严格递增，但可能跳跃。也不要把查不到当前对象当作“从未存在”；包装、删除、历史修剪和数据覆盖都需要进一步辨别。追踪历史要保留对应的事务与状态标记，让结论具有证据位置。

数据库可以帮助理解实体和关联，却不能替代协议访问规则。旧对象版本能被查询，不代表还能被用作新的可变输入。Shared 输入的初始共享版本也不等于本次实际执行版本。

现在面对一条对象记录，应能回答：它指向哪个身份、哪个版本，描述内容还是关系，位于哪笔事务与历史位置，以及能否支持当前状态结论。这些答案会在下一模块成为 Transaction Inputs 的基础。
