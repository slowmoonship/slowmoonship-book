# SUI 06 小结｜意图、结果和叙述是不同证据

Transaction 说明请求，Effects 说明执行状态与协议结果，Object State 说明特定版本内容，Move Event 说明程序显式发出的业务信息。分析时把它们连接起来，同时保留各自含义。

失败事务可以进入链上历史并收费。业务原子性不等于没有费用变化。统计成功率、成本或用户尝试时，必须确定分母是否包含失败，以及哪些提交前拒绝根本没有同类链上记录。

Object Change 摘要帮助定位结果，但不是全部业务语义。判断余额、归属或状态字段变化，需要精确版本与内容。原始 Effects 和平台派生列也有不同格式与版本，不能机械套用旧返回结构。

Event 不是自动状态流水。一个调用可能发出很多事件或没有事件；事件内对象 ID 不能单独证明对象被修改。路由中的多个 Swap Event，也不能当作同样多次独立用户交易。

最终结论应说明观察到什么、依靠哪层证据、是否成功、资金和对象结果是否覆盖完整。下一模块将这些结果放进 Checkpoint 与 Epoch，解释历史位置和时间口径。
